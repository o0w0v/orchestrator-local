# GUI版の使い方

普段の依頼は、これまでどおりAIとの会話で行います。この画面は、導入・起動と、手元の作業・ファイルの確認を担当します。

## 初めて使う

1. [Windows配布版](https://github.com/o0w0v/orchestrator-local/releases/tag/v0.2.0)のZIPをダウンロードし、固定の場所へすべて展開します。
2. `OrchestratorLocal.exe`をダブルクリックします。Pythonの別途インストールは不要です。`OrchestratorLocal.Runtime.exe`と`_internal`も同じフォルダに必要です。
3. 「初回設定」で、成果物の保存先と、既存の`ollama.exe`を選びます。モデルを独自の場所に置いている場合だけ「モデルの場所」も指定します。
4. 必要なら「PCへのログイン時に実行サービスを自動起動する」を選び、「設定を保存して接続を登録」を押します。
5. Codex側でMCP接続を再起動し、新しい会話を開きます。ホームの「起動」を押すと準備が整います。

既存のOllamaと、この版のGemma4:26bを実行できるWindows x64 PCが必要です。Ollama・モデルの導入や自動ダウンロードは行いません。モデルの版が一致しない場合は、生成せず状態に表示します。Ollama停止中はモデルの有無を断定せず、依頼時に確認します。

**現時点の接続自動登録先はCodexのMCP・Skillです。** 別クライアントへの自動登録はこの版に含みません。

## 毎日の使い方

- 「入力ファイルを追加」でCSV・JSON・TXT・MDをinboxへコピーできます。同名で内容が異なるファイルは別名にし、既存資料を上書きしません。1ファイル1MiB以下です。ファイルの追加だけでは生成しません。
- いつもの会話で、ファイル名と作業内容を依頼します。最初は「サンプルの依頼文をコピー」を使えます。
- 「作業履歴」には最近200件を表示します。「AIの確認待ち」は候補ができた状態です。会話側が元資料で確認・保存すると「完了」になり、「完成した成果物を開く」で保存先を開けます。
- 待機中・作業中の依頼は「選択した作業を中止」で中止を要求できます。GPUで処理が止まる時刻はOllama側にも依存します。

画面を閉じても実行サービスは継続します。停止したい場合は「停止」を押します。生成中なら中止の確認を表示します。ログイン時の自動起動は、初回設定のチェックを切り替えて「自動起動の設定を適用」で変更できます。サービスが待機しているだけではAIを呼びません。

## 保存先と更新

EXE版の設定は利用者の`LocalAppData/OrchestratorLocal/local-settings.json`、入力・成果物・ジョブは設定時に選んだ保存先へ置きます。既存のジョブ・成果物を自動移動・削除しません。保存先は初回設定後に保護されます。複数の保存先を使う開発者は`--config`で設定を分けられます。

更新やフォルダ移動の前に、旧版でサービスを停止し、自動起動を解除し、「接続登録を解除」を押します。展開先を置き換えた後、新版で同じ成果物の保存先を選んで登録してください。古いSkillを利用者が変更している場合や別の導入先が登録されている場合は、自動上書きせず案内を表示します。

以前のソース版から移る場合は、旧フォルダでREADMEの「更新・登録解除」を実行してからEXE版を設定します。成果物の保存先を引き継げば、既存履歴も表示できます。

接続登録解除と自動起動解除は別の操作です。登録解除後も入力資料・成果物は残ります。起動に失敗した場合は「ログフォルダを開く」からログを確認できます。

## 開発者向け

ソースからは依存関係を導入した後、`.venv\Scripts\pythonw.exe start-gui.pyw`で起動します。仮想環境を有効にした後は`python desktop_entry.py`でも起動できます。CLIも引き続き使えます。

Windows配布版の作成と検証：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.lock
.\.venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe packaging/build_windows.py
.\.venv\Scripts\python.exe packaging/smoke_windows.py dist/OrchestratorLocal --report validation-bundle.json
```

`dist`にZIP・SHA-256と展開済みアプリを作ります。GUIはウィンドウ用EXE、MCPはstdio用Runtime EXE、ログインサービスはGUI EXEの非表示モードです。設定・サービス・MCP・保存を共通利用し、GUI用のCloud呼び出しや再採点は追加しません。

検証は一時設定・一時Startupフォルダと仮のHTTPモデルだけを使います。実ユーザーの接続、自動起動、モデルには触れません。バイナリは未署名の初期版で、別PCでの受け入れ確認・OS再起動試験は別途必要です。
