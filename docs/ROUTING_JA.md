# いつものチャットで使う自動分担

Orchestrator Localを対応するデスクトップのローカル接続とSkillに登録し、電源ボタンをONにすると、いつもの依頼から適した作業をPC内のGemmaへ分担する。利用者が毎回モデル名を指定したり、別のGemma画面へ依頼を転記したりする必要はない。OFFや「今回は使わない」「この会話では使わない」を優先する。

## 裏側の流れ

1. 会話側が依頼と必要な資料・条件を整理する。挨拶や単純な説明まで分担の工程を増やさない。
2. 対象の成果物作業を`route_task`へ渡し、Luna lowが1回だけ振り分ける。
3. 小さい・分担に向かない仕事は会話側が直接処理。向いている仕事はGemmaへ。接続や担当境界が必要な時だけ、会話側が短く設計する。
4. 会話側が元資料と候補を直接確認する。使える原物は採用し、利用を誤らせる問題だけ差分修復する。合格後に任意の改善案を並べたり、文体の好みで作り直したりしない。
5. 同じチャットで、成果物と必要な結論を受け取る。

最終確認はその会話のモデルが行う。会話モデルがSolならSol確認になる。Skillが任意の会話を自動的にSolへ切り替える機能はなく、別の確認AIも追加しない。

Gemmaによるコード案も扱えるが、500件の根拠はデータ作業である。GUI全体の丸投げで同じ効果が出るとはしない。コードでは会話側が実行・必要な動作確認を担当し、未確認を確認済みとは表示しない。

## 条件の食い違いを減らす

型・順序・例外など必要な条件は短い`inputs.work_contract`にまとめ、Luna・Gemmaへ同じ内容を渡す。候補取得時には元依頼・同じ入力とdata_schemaが確認側へ戻る。例えば、証跡IDを求める場合は「起点レコード自身を含むか」「どの参照順か」を事前に明確にする。標準は起点を含む参照順とし、利用者の明示指定を優先する。依頼にない証跡列を新たに要求しない。

```json
{"work_contract":{"evidence_ids":"参照元request.id、catalog.id、teams.idを、この順で含める"}}
```

## 接続と消費

Luna振り分けには、既に導入・ChatGPTログインされたCodex CLIを使う。モデルは`gpt-6-luna`、effort low、Standard指定で、Cloud消費がある。CLIの自動導入やAPIキーによる別課金への切替は行わない。既存CLIを自動検出できない環境では、`local-settings.json`の`routing_codex_exe`へ既存codex.exeのパスを指定できる。`routing_enabled:false`ならLunaを使わず通常処理へ戻る。

OFF・今回使わない指定ではLunaもGemmaも新規呼出ししない。同じ依頼キーの再送は保存済みの振り分けを返す。失敗・中断した振り分けも勝手に再生成せず、通常の会話側へ戻す。Gemma作業中にCloud coordinatorを待機させる専用プロセスは起動しない。ホストのチャット自体の待機・確認消費は、このアプリだけで制御・完全測定するものではない。

振り分けの元入力・応答・usage metadataはデータフォルダの`routing`に保存する。usageが欠測した失敗を0として記録しない。HTTP429後の再送警告だけで仮想の追加料金を足さず、成功usageを一度だけ数える。

## 対応チャット

ローカルMCPとSkillを利用できる、このPCの接続済みチャットが対象。登録後にMCP接続を再起動し、新しいチャットを開く。接続やSkillを持たないWeb・モバイル・別PCの会話まで自動で有効になるものではない。専用ツールが見えずローカルシェルが使える場合は、Skillの補助経路を会話側が使える。

[公式のデスクトップMCP説明](https://learn.chatgpt.com/docs/extend/mcp)と[Skillsの役割](https://developers.openai.com/plugins/concepts/skills)も参照。

## 測定根拠

新規500依頼（25既知型の合成データ作業）で、通常Sol 443.53593、新方式258.0112670 Credits相当、振り分け・設計・確認・修復込みで約41.8%減。固定正解との一致は500/500と499/500。不一致は正しい宛先に付す証跡の起点IDの解釈差で、公開契約の曖昧さを残す。今回、担当間で同じ明示条件を共有する形にした。これを採点後に500/500へ書き換えたり、今回のアプリで品質完全同等・同じ節約率を保証したりはしない。171件は同一のSol直行実行を共有し、異なる経路の比較は329組。親の研究準備・監視・報告費は運用比較へ混ぜていない。実請求明細は未測定で、固定Standardレートによる報告usage換算である。
